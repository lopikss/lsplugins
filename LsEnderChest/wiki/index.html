LsEnderChest 2.0.0 Paper 26.3 Java 25

Ender Chests, rebuilt for servers.

LsEnderChest replaces vanilla Ender Chest storage with a permission-based 1–6 row system and adds the tooling a real server needs: live staff access, restore history, safe overflow protection, built-in vanilla migration, SQLite/MySQL storage, and per-player audit logs.

What changed in 2.0?

R

Restore history

Open a GUI, preview historical sessions, and safely restore a player's chest. The current state is backed up first.

O

Overflow protection

If a player loses row permissions, extra items are moved into a protected one-time Overflow Chest instead of disappearing.

A

Live admin access

Admins can open a chest while the owner is using it. Both interact with the same live inventory instead of stale copies.

C

Built-in conversion

The old standalone converter is no longer required. Vanilla Ender Chest migration is built directly into LsEnderChest.

L

Per-player journals

Audit logs are stored per chest owner using UUID filenames, with the real actor recorded for player and admin actions.

S

Safer storage

Ordered storage work, shared live sessions, one-time overflow claims, and protected maintenance operations reduce stale-save and dupe risks.

Getting started

Installation

A normal installation takes a few minutes. SQLite works out of the box, so MySQL is optional.

Download LsEnderChest 2.0.0 from Modrinth.
Place the JAR inside your server's plugins/ folder.
Start or restart the server. LsEnderChest will create its configuration and internal data files.
Assign enderchest.rows.1 through enderchest.rows.6 to your ranks. Players without one use settings.default-rows.
Test /ec in game. /lsec and /enderchest work the same way.
Using EssentialsX? LsEnderChest intentionally owns the bare /ec and /enderchest labels when both plugins are installed.

LsEnderChest 2.0

Features

The plugin stays focused on Ender Chest storage, but 2.0 adds much stronger recovery and administration tools.

Expandable storage

Give players 1–6 rows using permissions. The highest row permission wins.

Shared live sessions

Owners and authorized admins can interact with the same live inventory at the same time.

GUI restore history

Session snapshots can be previewed and restored with confirmation.

Overflow Chests

Permission downgrades no longer make items outside the new size disappear.

Built-in conversion

Safely migrate vanilla Ender Chest contents without a separate converter plugin.

Per-player audit logs

Each chest owner gets a UUID journal containing player, admin, conversion, overflow, and restore activity.

SQLite & MySQL

Use local storage by default or connect to an external MySQL database.

Blocked-item rules

Blacklist/whitelist support for materials, lore, and supported item data components.

Update checker

Admins can receive a clickable notification when a newer plugin version is published.

Usage

Commands

/ec, /lsec, and /enderchest are equivalent root commands.

/ecOpen your own LsEnderChest.
/ec <player>Open another player's chest. Admins can edit; view-only users depend on permission.
/ec restore <player>Open the restore-history GUI for a player.
/ec convert <player>Run the built-in vanilla conversion for one online player.
/ec convert allArm a bulk conversion. It does not start until confirmed.
/ec confirmConfirm the pending dangerous action. Bulk conversion confirmations expire after 30 seconds.
/ec reloadReload supported configuration, messages, titles, rules, and runtime files.
Every command above can also use /lsec or /enderchest instead of /ec.

Recovery

Restore system

Restore points are session-based, so one chest open → close cycle becomes one useful snapshot instead of hundreds of tiny click events.

How a restore works

/ec restore <player>→ Choose session→ Preview contents→ Confirm→ Restore

Session snapshots

A session starts when the chest is opened and ends when the final editable viewer closes it.

Pre-restore backup

The current state is backed up before a historical state is applied, so an accidental restore can itself be undone.

Admin-safe

The GUI includes history, preview, and confirmation instead of applying a rollback on the first click.

Overflow-aware

Historical Overflow Chests get safe backing storage when restored instead of reusing already-claimed overflow records.

Restore is intentionally an administrative feature. A normal player restoring old items after removing them would create an obvious duplication path.
Item safety

Overflow protection

When a player's allowed chest size gets smaller, LsEnderChest protects everything that no longer fits.

Example: 4 rows → 1 row

Slots 1–8 stay where they are. Everything from slot 9 onward is moved into an Overflow Chest, and the Overflow Chest becomes slot 9.

Not portable storage

The item never opens a storage GUI. Players cannot add extra items to it.

One-time recovery

Right-clicking consumes the token and drops every protected item on the ground at the player's location.

Server-backed contents

Real contents are stored server-side. The chest item carries protected metadata identifying its backing record.

Configurable lore

The displayed lore supports color codes and placeholders such as %items%, %created%, %source_rows%, and %target_rows%.

Copying the visible name or lore does not create a valid Overflow Chest. The real record must exist and be successfully claimed.
Migration

Built-in conversion

LsEnderChest 2.0 replaces the old standalone LsEnderChestConverter with migration built into the main plugin.

The player's vanilla Ender Chest contents are read.
LsEnderChest writes the converted contents into custom storage.
The original vanilla snapshot is verified again.
Only after custom storage succeeds are the vanilla contents cleared.
The player is marked converted so automatic migration does not repeat.

Commands

/ec convert <player>Convert one online player.
/ec convert allArm conversion for eligible online players. Nothing changes yet.
/ec confirmConfirm the pending bulk operation before it expires.
If you still have the standalone LsEnderChestConverter installed, remove it when moving to 2.0.0. Conversion belongs to the main plugin now.
Audit trail

Logging & audit

2.0 removes the old global simple/detailed log model and gives each chest owner a dedicated UUID journal.

Journal path
plugins/LsEnderChest/logs/players/<uuid>.log

Individual actions

Item additions/removals, opens, blocked attempts, conversion, overflow, and restore activity can be audited.

Real actor recorded

If an admin modifies somebody else's chest, the target player's journal records which admin performed the action.

Session restore points

Restore history is grouped by chest session rather than every item click.

Legacy logs

Older simple.log and detailed.log files are treated as legacy data rather than the active 2.0 logging model.

Turning verbose logging off does not remove the restore records needed for /ec restore.
Data

Storage

LsEnderChest stores custom chest data outside vanilla Ender Chest storage so variable sizes, offline access, restores, and overflow records can work reliably.

SQLite

Recommended for a normal single server. No external database server is required. The default database lives under plugins/LsEnderChest/EnderChest/database.db.

MySQL

Use an external MySQL database when your setup requires centralized database infrastructure.

Changing storage type or UUID mode is not a normal hot-reload change. Restart the server after changing those settings.
Configuration

Configuration

The defaults are designed to work for most servers. Storage/UUID changes require a restart; normal presentation and behavior settings can be reloaded.

settings.online-mode

Use authenticated/proxy-forwarded UUIDs when true. Changing UUID mode after data exists can make old storage appear under another UUID.

settings.default-rows

Fallback row count (1–6) when a player has no enderchest.rows.* permission.

conversion.convert-on-first-join

Automatically migrate vanilla Ender Chest contents once when a player joins.

restore.max-history

Controls how many restore points are loaded into the restore-history GUI.

updates.*

Enable update checks and admin notifications. Updates are never installed automatically.

overflow-chest.lore

Customize newly generated Overflow Chest lore with colors and placeholders.

Recommended config structure

config.yml
storage:
  type: "sqlite"

  sqlite:
    file: "EnderChest/database.db"

  mysql:
    host: "localhost"
    port: 3306
    database: "lsenderchest"
    username: "user"
    password: "password"
    parameters: "?useSSL=false&autoReconnect=true"

settings:
  online-mode: true
  default-rows: 1
  tab-complete-offline-players: true

conversion:
  convert-on-first-join: true

logging:
  enabled: true

restore:
  max-history: 100

updates:
  enabled: true
  notify-admins: true

title:
  chest: "%player%'s Ender Chest"

overflow-chest:
  lore:
    - "&7Extra items that no longer fit in your Ender Chest."
    - ""
    - "&fItems: &e%items%"
    - "&fCreated: &7%created%"
    - ""
    - "&bRight-click to release all items"
    - "&8Contents will be dropped on the ground."
    - "&8One-time use • Cannot be placed"
Overflow lore placeholders: %items%, %created%, %source_rows%, and %target_rows%.
Restrictions

Blocked items

Use blocked-items.yml to blacklist matches or switch to whitelist mode.

Materials

Match Paper/Minecraft material names such as DRAGON_EGG or PLAYER_HEAD.

Lore

Match plain-text lore lines. Legacy & color codes are ignored while comparing.

Data components

Block supported item data components such as CUSTOM_MODEL_DATA.

Bypass

enderchest.blocked.bypass allows trusted users to ignore restrictions.

blocked-items.yml
mode: BLACKLIST

blocked-items:
  - DRAGON_EGG
  - PLAYER_HEAD

blocked-lore:
  - Soulbound

blocked-components:
  - CUSTOM_MODEL_DATA
Internal files

Internal data

Runtime state that server owners should normally leave alone is kept under the EnderChest/ subfolder instead of cluttering the plugin root.

plugins/LsEnderChest/ ├── config.yml ├── config-guide.yml ├── blocked-items.yml ├── logs/ └── EnderChest/ ├── README.txt ├── database.db ├── converted-players.yml ├── row-state.yml └── overflow-secret.key

database.db

SQLite player/overflow storage when SQLite is enabled.

converted-players.yml

Tracks players whose vanilla Ender Chest has already been converted.

row-state.yml

Tracks last-known row counts so permission downgrades can be detected safely.

overflow-secret.key

Security key used to verify genuine Overflow Chest recovery items.

Do not edit, delete, move, or replace files in this folder unless you know exactly what you are doing. In particular, changing or deleting overflow-secret.key can invalidate existing Overflow Chests.
